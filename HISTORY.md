# METOYO — Development History & Provenance

## Purpose

This file preserves the sequence of development so that future refactoring does not erase how the project evolved.

The repository deliberately distinguishes **historical provenance** from **current canonical terminology**.

---

## Period I — The Gift Whisperer system build

### July 2025

The project was developed as **The Gift Whisperer**.

Core work included:
- problem framing around memory, emotional presence and gifting;
- narrative anchor and ritual language;
- memory-cluster input;
- relational persona system;
- Trident output: Gift / Source / Ritual;
- Gesture Grammar;
- Spatial Memory Architecture;
- Reflection Chamber;
- prompt and tone logic;
- lightweight technical architecture;
- privacy / forget-by-default thinking;
- contributor agreements;
- Swedish technology sourcing strategy;
- project plan, budget and workflow;
- ritual and strategic presentation decks.

The engine's foundational idea was that users should begin from remembered fragments rather than product search.

The project was framed as a cultural artifact / soft system rather than a conventional commerce product.

---

## Period II — METOYO overlay

### January 2026

A canonical identity decision introduced **METOYO** as the public-facing brand, condition and ritual space.

The existing system was not discarded.

Instead:

```text
METOYO
  public-facing condition / ritual space
      contains
THE GIFT WHISPERER
  internal operational engine
```

The naming rule became:

> **METOYO names the space and condition; The Gift Whisperer runs the place.**

The Gift Whisperer was described as a "working dwarf": an internal actor that does the work without claiming the public stage.

The public tagline became:

> **When there is room for more.**

The "room" concept reinforced:
- invitation rather than interruption;
- no urgency;
- no gamification;
- no coercive loops;
- no growth-marketing pressure;
- space for reflection and refusal;
- a system designed to disappear.

---

## Period III — Canonical repository consolidation

### 23 September 2026

`Hybrismannen/metoyo` was initialized as the canonical repository.

Objectives:
- preserve all known METOYO / Gift Whisperer concepts;
- separate current doctrine from historical implementation choices;
- make the system intelligible without relying on presentation decks;
- create machine-readable registries for personas, gesture grammar and Trident;
- expose ethical/data constraints as architecture;
- preserve source inventory and provenance;
- prepare for later implementation without prematurely locking to an old stack.

---

## Versioning doctrine

### Historical artifacts
Do not silently rewrite.

### Canonical specifications
May be updated through explicit versioned decisions.

### Machine-readable registries
Must track schema-compatible changes.

### Implementation
Must conform to canonical specifications or document the deviation.

---

## Naming migration rule

Do **not** perform a global search-and-replace from "The Gift Whisperer" to "METOYO."

Correct transformation depends on the referent:

- public ritual space → METOYO;
- internal engine → The Gift Whisperer;
- 2025 source title → preserve The Gift Whisperer;
- current system narrative → METOYO with Gift Whisperer engine;
- future agent implementation → explicit decision required.

---

## Canonical continuity

The project changed its public name/frame without changing its deepest system commitments:

```text
memory
→ relation
→ evocation
→ Trident
→ gesture
→ optional reflection
```

That continuity is the core of METOYO's provenance.
