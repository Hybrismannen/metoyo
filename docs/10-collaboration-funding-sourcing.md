# 10 — Collaboration, Funding & Sourcing

## 1. Collaboration posture

METOYO's historical development model is collaborative, commons-oriented, and non-commercial in the prototype phase.

The project has been formally anchored under:

**Form & Flöde – Organisations- och Processutveckling i Sverige**

The source corpus contains contributor agreements in both English and Swedish.

## 2. Roles

Relevant contributor roles include:
- frontend/backend developer;
- UX/interactions designer;
- prompt engineer or AI curator;
- privacy/legal advisor;
- writer/editor;
- illustrator/symbol designer;
- systems architect;
- localization contributor;
- cultural/ritual reviewer;
- research/evaluation collaborator.

## 3. Contributor commitments

Historical agreements require contributors to respect:
- confidentiality of non-public material;
- no reuse of user data for external training;
- data minimization;
- non-surveillance design;
- project tone;
- CC BY-NC-SA 4.0 licensing posture;
- attribution;
- non-commercial project logic.

Technical debugging logs were historically specified as anonymized and removed within no more than 14 days.

Any future agreement should receive contemporary legal review before signature.

## 4. Compensation model in source materials

Historical prototype-stage options:
- voluntary/pro bono contribution;
- portfolio collaboration;
- grant-supported paid work.

The agreements state that, when funding is secured, compensation should be:
- transparent;
- equitable;
- documented;
- optional for the contributor to accept or decline.

Historical language also contemplated retroactive compensation for prior documented work.

## 9. Collaboration sequence

A current contributor onboarding flow should be:

```text
1. Read canonical identity
2. Read system model
3. Read ethics/privacy doctrine
4. Identify bounded work package
5. Review source provenance
6. Agree contribution/licensing terms
7. Work in versioned branch/PR
8. Review for ritual + technical integrity
9. Merge with decision trace
```

## 10. Outreach narrative

The collaborator invitation should emphasize:
- not a conventional startup;
- meaningful bounded challenge;
- strong conceptual system;
- privacy-first architecture;
- poetic UX;
- memory-to-gesture logic;
- contributor credit;
- transparent funding posture.

Avoid overselling speculative impact.

## 11. Stewardship

Historical materials proposed a future rotating **Whisper Circle** to review prompts, rituals and submissions.

This is a design concept, not an activated governing body.

If established, its charter should define:
- membership;
- decision rights;
- rotation;
- conflict handling;
- privacy access;
- editorial authority;
- versioning responsibility.

## 12. Principle

> A ritual system needs custodianship more than growth ownership.

Collaboration should strengthen the system's integrity rather than turn contribution into feature accumulation.
