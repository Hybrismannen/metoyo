# METOYO — Source Index

## 1. Purpose

This index records the source artifacts used to consolidate the repository.

The source set is primarily **internal project documentation**, not independent empirical validation.

Accordingly, distinguish:

- **PROJECT DECISION** — a design/naming/governance choice made inside the project.
- **PROJECT HYPOTHESIS** — a proposed effect or strategic belief that may require testing.
- **HISTORICAL PLAN** — a dated implementation/budget/roadmap choice.
- **EXTERNAL CLAIM** — a claim requiring independent source verification before public factual use.

This evidence discipline follows the project's Pius/HARP emphasis on source verification, auditability, and referential control.

## 3. METOYO naming directive

Across the revised project materials, the following directive is repeated:

- METOYO is the public-facing brand/condition/ritual space.
- The Gift Whisperer is the internal operating engine.
- underlying prompts/personas/routines/architecture remain valid.
- the name change is a narrative/public overlay, not an erasure of the engine.

This repository treats that directive as **CANONICAL PROJECT DECISION**.

## 5. Claims requiring future evidence audit

Before public factual publication, independently verify claims relating to:
- gender differences in gifting/emotional labor;
- "first mover" or "no competitor" assertions;
- effects on emotional fluency;
- effects on gift anxiety;
- causal relationship effects;
- current market landscape;
- active grant programs;
- current legal/GDPR interpretation;
- named technology providers' data-use policies;
- any statistics used in decks.

Narrative examples must also be clearly labelled fictional/composite if they are not documented real cases.

## 6. Repository source standard

When adding a new factual claim, record:

```yaml
claim:
type: project_decision | project_hypothesis | historical_plan | external_claim
source:
date:
verified:
notes:
```

This prevents poetic system language from silently becoming empirical fact.
